# 飞书 Codex 机器人：开源依赖架构

当前实现替换了旧的内部 LarkLink 部署方案。

```text
飞书事件长连接 → 官方 Node SDK → 本项目 Bridge → ACP SDK → Codex ACP → Codex CLI
                                      ↓
                              用户白名单 / 任务队列
                              一次性审批 / 会话存储
                              每会话 Git worktree
```

飞书 SDK 负责认证与长连接，项目自行实现事件过滤、持久化去重、限长消息队列、
权限请求转发和响应。ACP 使用官方协议 SDK，无内部包或协议实现复制。
Codex ACP 的公开 npm 包携带开源 Codex CLI，安装及依赖完整性由 lockfile 固定。

每次恢复 ACP 会话都显式设置 read-only 模式，防止继承 full-access 配置。
文件与终端能力不向 Agent 声明，由 Codex 自身的工具和沙箱执行；遇到权限请求时，
仅允许原消息发送者在同一飞书对话选择 allow_once/reject_once。权限超时自动取消。

持久化策略是先记录消息 ID 再处理，重启后不自动重放潜在副作用；这意味着运行中
崩溃的消息可能需要用户重新发送。会话 ID 恢复失败时明确报错，可用 /new 新建会话。
worktree 持久保留，不执行自动清理。Git worktree 不替代操作系统隔离。

独立 runtime CLI 提供 bots add/setup/config/start/stop/status/doctor 和前台运行；
部署工具保留 systemd、supervisor 配置渲染、模型发现、模型连通性检查与代理设置。
当前桥接仅处理文本，最终回复按段发送，不包含旧方案的 Web 工作台或互动卡片能力。

基础功能只访问公共 npm、飞书开放平台和用户配置的模型服务。
Codebase MR 准备是可选的 Git 集成，保留在 src/review.ts，不是私有包依赖。
依赖许可检查见 scripts/audit-dependencies.ts 和 THIRD_PARTY_NOTICES.md。

## 多引擎与模型选择

新增 Claude CLI 流式控制适配，不引入 Claude SDK npm 包。
模型列表由 Codex model/list 和 Claude initialize.models 动态提供。
/models 生成带随机令牌的飞书下拉卡片，card.action.trigger 同步检查操作者、
对话、卡片消息 ID、有效期和服务端模型选项，快速返回 toast 后按会话队列切换。
切换确认成功后才保存 provider、每引擎 model 与 sessionId；失败保留原设置。
Codex 恢复后通过 ACP 配置协议设置模型；Claude 通过 set_model 控制请求设置。
两种引擎共用 worktree，独立保存对话历史。

Codex 模型目录保留 supportedReasoningEfforts/defaultReasoningEffort。
卡片服务端选项逐模型展开为 model+effort，客户端只回传受限索引。
持久化模型 ID 与 reasoningEfforts.codex，恢复时先模型后强度调用 ACP 配置接口。
没有支持信息时不伪造四档；默认档位同样读取元数据。

## 工作空间准备

src/workspaces.ts 负责校验来源、克隆指定分支或初始化空 Git 项目。
代码先写入根目录下的随机临时目录，确认 HEAD 有效、写入 workspace.json 后再移动到最终目录。
同名目录只有元数据和来源校验通过才复用，不执行自动拉取或覆盖本地修改。
deploy --repo/--workspace 在项目预检之前准备工作空间，之后沿用原模型检查、配置和服务流程。
此入口是命令行功能，尚未接入飞书卡片。
